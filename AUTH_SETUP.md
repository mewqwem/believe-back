# Власні акаунти: поточний етап

Реалізовано реєстрацію, вхід, вихід, приватну сторінку акаунта та сесії на 7 днів. Ім’я, email і дата реєстрації відображаються в акаунті. Зміна імені/аватара, ігрова статистика, підтвердження пошти та відновлення пароля ще не реалізовані. Ігровий playerId наразі залишається окремою гостьовою ідентичністю; статистику не можна прив’язувати до нього як до підтвердженого акаунта.

## Запуск

Бекенд: `.env` містить `MONGODB_URI`; `MONGODB_DB` типово `believe_dev`. `npm run dev` запускає порт 3000. За `SKIP_DB=true` гра працює, а `/auth/*` повертає 503. Помилка БД не перешкоджає гостьовій грі.

Фронтенд (`../believe-front`): `npm run dev`, порт 3001. Серверна змінна `AUTH_BACKEND_URL` типово `http://127.0.0.1:3000`. Для розгортання встановити її явно; `APP_ORIGIN` — точний публічний origin фронтенду (схема + хост + порт без кінцевого `/`). У production потрібен HTTPS; cookie має Secure. Секрети не використовують префікс NEXT_PUBLIC.

## Потік

Браузер → Next `/api/auth/register|login|logout` → Express `/auth/*` → MongoDB.

- Next перевіряє Origin, JSON і ліміт тіла 16 KiB. Токен із бекенду записується лише в HttpOnly cookie `bluff_session` (SameSite=Lax, Path=/), не в JSON браузеру.
- Express приймає сесію тільки через Bearer Authorization. Він не автентифікує за cookie браузера або клієнтським playerId.
- `users`: нормалізований унікальний email, name, прихований passwordHash (Argon2id), avatar, timestamps.
- `sessions`: userId, SHA-256 хеш 32 випадкових байтів токена, expiresAt. TTL очищає записи; `/auth/me` перевіряє строк самостійно, незалежно від очищення TTL.
- Вихід видаляє серверну сесію, після успіху Next очищає cookie. При збої сервера UI не стверджує, що вихід завершився.
- `proxy.ts` виконує лише попередню перевірку формату cookie. Account layout/page читають сесію з бекенду; сама наявність cookie не дає доступу.
- `/login` і `/register` перенаправляють користувача з дійсною сесією на перевірений локальний `next`. `/` та `/room/*` не захищені й доступні гостям.
- Ліміти спроб: 100 на IP бекенду та 10 на нормалізований email за 15 хвилин. За Next-проксі IP-ліміт спільний для запитів цього фронтенду. Лічильники в пам’яті одного процесу: для кількох реплік потрібне спільне сховище й окреме налаштування довіреного проксі.

## Перевірки

- `npm test`: локальні перевірки Argon2 і валідації.
- `npm run test:auth`: Atlas + тимчасовий HTTP-сервер. Створює один унікальний тестовий акаунт і видаляє лише його та його сесії.
- `npm run test:auth:frontend`: потрібні запущені бекенд 3000 та фронтенд 3001; перевіряє cookie, CSRF, редіректи, вихід і гру двох гостей. Аналогічно видаляє свій тестовий акаунт. `TEST_FRONTEND_URL` змінює адресу фронтенду.
- У фронтенді: `npm run lint`, `npx tsc --noEmit`, `npm run build`.
